# Rickipedia — лабораторная работа 4

Работа выполнена по `../assignment.docx` и продолжает проект лабораторной №3.
Первый экран загружает первую страницу Rick and Morty API через Dio и BLoC.

## Запуск

Требуются Flutter 3.47.4 / Dart 3.13.3 либо совместимая версия и интернет.

```powershell
flutter pub get
dart run build_runner build
flutter run -d chrome
```

Сгенерированный `character.g.dart` уже входит в исходники. Повторная генерация
нужна при изменении модели. Точные версии закреплены в `pubspec.lock`.

## Возможности

- Живой GET `https://rickandmortyapi.com/api/character?page=1`, без токена.
- Модели Character и CharacterPlace с json_serializable и Equatable.
- Интерфейс репозитория отделяет источник данных от HomeBloc.
- HomeLoad → загрузка → успешный список или сообщение об ошибке.
- Тайм-ауты по 10 секунд, обработка HTTP-ошибок и неверной структуры JSON.
- Повторный запрос, кнопка обновления и pull-to-refresh.
- Отдельное состояние пустого списка и защита от дублирующих запросов.
- Логи Dio и BLoC через Talker; регистрация зависимостей через GetIt.
- Сетевые изображения с заглушкой при ошибке.
- Переход к подробностям выбранной записи и возврат в каталог.

Загружается первая страница (до 20 персонажей). Пагинация и отдельный запрос
подробностей не входят в лабораторную №4. Прямая ссылка вида
`/#/home/character/2` разрешается по первой странице после её загрузки;
ID вне загруженной страницы показывает сообщение об отсутствии персонажа.
Имена, пол и названия мест выводятся на языке API. Статус и основные виды
переведены для интерфейса; вымышленные биографии не используются.

## Архитектура

`HomeScreen → HomeLoad → HomeBloc → CharacterRepositoryInterface → Dio → API`

`lib/data/dio/set_up.dart` — клиент и перехватчик логов.
`lib/data/endpoints.dart` — конечные точки.
`lib/data/repositories/characters/` — интерфейс, реализация и модели.
`lib/app/features/home/bloc/` — событие, состояния и BLoC.
`lib/app/features/home/home_screen.dart` — BlocBuilder и обновление.
`lib/di/di.dart` — зависимости и TalkerBlocObserver.

BLoC хранит загруженные модели для переходов к подробностям. Клиент и BLoC
освобождаются при сбросе контейнера зависимостей. Успешный список неизменяемый.

## Проверка

```powershell
flutter analyze
flutter test
flutter build web --no-web-resources-cdn
```

23 автоматических теста проверяют сериализацию, вложенные поля, HTTP-запрос,
ошибки 500/503 и тайм-аут, неверный JSON, состояния BLoC, повторную загрузку,
пустой список, конкурентные события, pull-to-refresh, навигацию и адаптацию
при 320/1100 px с масштабом текста 150%. Тесты не зависят от внешнего API.

В браузере отдельно проверены живой ответ API, загрузка, карточка, возврат,
контролируемый HTTP 503 и восстановление через настоящий API.

Проверена веб-версия. Нативные сборки и запуск на Android/iOS-эмуляторе или
физическом устройстве не выполнены. INTERNET в AndroidManifest.xml и разрешение
исходящих соединений macOS добавлены, но нативная проверка ещё нужна.

При проблемах с кириллицей в пути используйте свободную букву диска:

```powershell
subst K: (Get-Location).Path
Set-Location K:\
flutter test
```

Исходные каталоги Windows/Linux находятся в `../platforms`, как в работе №3.
Для настольной сборки перенесите соответствующий каталог в корень приложения
и подготовьте окружение Flutter с поддержкой символических ссылок.
